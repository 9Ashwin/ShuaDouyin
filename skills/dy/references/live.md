# 直播

直播间是 `live.douyin.com/<房间号>`。它和推荐流是两套页面：弹幕、礼物面板、主播信息都有各自的定位。

## 先看清再说话

```bash
dy live info     # 主播名、是否在播、能不能评论
dy live chat     # 当前加载的弹幕
```

`live info` 的 `host` 来自页面标题前缀，不是页面上第一个昵称——侧边的观众列表里也有昵称，读错会把观众当主播。

`live.chat` 只返回**当前已加载**的弹幕，标 `complete: false`。滚出视口的旧弹幕不在里面。

每条弹幕带 `kind`：`chat` / `gift` / `join` / `system`。

- `chat` — 有人在说话，带 `author`
- `gift` — 有人送了礼物，`author` 是送礼的人
- `join` — 进场提示
- `system` — 平台公告、禁言提示

判 `chat` 和 `join` 靠**作者和正文之间有没有分隔符**，不靠句式。「XXX：一下就回来了」以「来了」结尾，按句式会被误判成进场——这个错误真的发生过。

## 画面读不到

**直播画面是 canvas，没有任何文字层。** `video_readable` 恒为 `false`。游戏名、英雄、比分、经济都读不到。

要看懂实况只能连续高频截图并对比。单帧不作为判断依据，更不能凭技能图标猜英雄——凭图标猜过一次，观众当场质疑，事后确认猜错。

**只能说屏幕上写着的字**，不说需要连续观察才成立的结论。

## 发弹幕

```bash
dy live say --text "…" --request-id <唯一ID>
```

弹幕走的是平台的 Slate 富文本编辑器，不是普通 input。发送后命令会读聊天区，确认这行真的出现了（`seen_in_chat: 1`）才报 `confirmed`。

**短句、多条、口语化**比一段长文更像真人。一次发一句，中间留出别的观众插话的间隔。

## 礼物会花真钱

```bash
dy live gifts                                        # 先看面板里有什么、多少钱
dy live gift --name 人气票 --price 1 --request-id <id>
dy live gift --name 加油鸭 --price 15 --count 1
```

规则：

1. **必须先 `live gifts` 看真实价格。** 按钮标签形如 `15钻加油鸭15钻赠送`，名字夹在两个价格中间。
2. **`--name` 和 `--price` 必须同时匹配。** 只给名字可能点到同类里更贵的那个。
3. **发送后核对聊天区实际送出了什么。** 返回值里的 `unexpected` 列出多送的东西。
4. 礼物面板的类名每次构建都变，只能用可见文本定位。一次走查用宽泛的类名选择器点了一下，实际送出「人气票 ×2 + 加油鸭 ×1」，比预期多也更贵。

礼物不可撤销。用户没说可以送，就不要送；余额是真实的钱。

## 和其他命令的配合

- 直播页和作品页是不同的标签。CLI 会按命令自己选标签：`live.*` 认 `live.douyin.com` 那个，作品类命令认作品标签。所以直播开着也能同时读作品，不用手动切。
- 评论区和直播间的 `page.facts` 标记不一样，定位失败时先跑 `dy page facts` 看页面到底有什么。
