# 浏览与成长

## 每一轮的原则

使用 CLI 返回的稳定 ID。采样画面不等于完整观看，评论和私信按用户授权执行。

每轮浏览后调用 `growth review`，按返回顺序处理活动记录；`event:<账号>:<id>` 是操作素材的来源，不自动证明内容正确。

## 看作品

每条作品先读 `video info`，按目标选择观察、跳过或搜索。评论只读到已加载部分，`complete: false` 表示这不是全部。

`video observe` 截取浏览器视口：滚动后画面可能不包含作品，暂停时还可能重复，须逐帧确认实际内容。

## 互动前

重新核对作品、评论或会话的稳定 ID。页面变化就放弃旧决定，不要拿旧决定套新页面。

评论和聊天回应对方的具体内容，不编造经历、听到的声音或看过的画面。没有合适内容可以不发，这是常态。

**不要把自己的调试过程写成评论。** 「测试一下」「验证能否发送」「第一次就该成功」这类句子对外部读者毫无意义：它们出现在真实作品下面，会让人莫名其妙，而且公开可见、撤不回。评论是给作者和其他观众看的，测试是给自己看的，两者不能混。

需要验证发送链路时，用 AI 测试群，不要拿陌生人的作品当试验田。确实要在评论区验证时，写一句哪怕普通但成立的回应（对内容本身说的话），而不是写「在测功能」。

## 分享

分享前判断是否符合对方当前话题和兴趣：

- `chat share` 是文字链接
- `chat forward` 是原生作品卡片

面板变化不是送达证据。结果不明时核对收据和页面，不换 request ID 重发。

## 发图片

用户要求发送图片时，可以先由当前 agent 的图片生成能力产出本地图片。

```bash
# 私信
dy chat image --conversation-id <会话ID> --image <文件路径> --request-id <唯一ID>
# 作品顶层图片评论
dy comment image --video-id <作品ID> --image <文件路径> --request-id <唯一ID>
```

评论支持 PNG/JPEG，私信还支持 GIF。先用 `--dry-run` 核对文件与目标。正式操作会检查已有草稿、目标和图片预览。

`delivery_uncertain` 需要核对收据与页面，不能自动重发或说成已送达。图文作品发布需先查看当前命令能力，不要假称已经支持。
